## What it is

A **DeepSeek Harness plugin** that exposes your Jimeng account's generation
capabilities inside the conversation.

Not just Seedance. Whatever your account can use, the plugin can call:

**16 image models** — Seedream 5.5 / 5.0 Pro / 5.0 Aurora / 5.0 Surge / 5.0 Flash / 5.0 Lite, Jimeng ImageMax 1.0, Aesthetics V8.2, Anycook 1.0, Seedream 4.7 / 4.6 / 4.5 / 4.1 / 4.0 / 3.1 / 3.0

**18 video models** — Seedance 2.5 / 2.5 Flash / 2.5 draft, the whole Seedance 2.0 family, Seedance 1.0, Wan 3.0 / 3.0 Prime, Vidu Q3 / Q2, HappyHorse 1.1 / 1.0

> That list is **read live from your account**, not hard-coded. Different tier, new
> release, delisted model — the list follows automatically.

| Tool | What it does | Costs credits |
| --- | --- | --- |
| `jimeng_models` | List every model the account can use | ❌ free |
| `jimeng_status` | Sign-in state and remaining credits | ❌ free |
| `jimeng_image` | Text-to-image, saved into the workspace | ✅ |
| `jimeng_video` | Text-to-video, saved into the workspace | ✅ |

## Credit safety

Generation costs real credits, so there are four gates:

| Gate | How | Effect |
| --- | --- | --- |
| **`dryRun`** | add `dryRun: true` to any generator | Builds and returns the request, **submits nothing** |
| **Free tools** | `jimeng_models` / `jimeng_status` | Inspect models and balance for free |
| **`minCreditsToKeep`** | set to `50` | Refuses to submit at or below 50 |
| **`allowSpend`** | set to `false` | Every spending tool refuses; queries still work |

```yaml
- id: jimeng-seedance
  name: '@local/dsh-jimeng-seedance'
  config:
    minCreditsToKeep: 50
    allowSpend: true
```

## Install

Requires DeepSeek Harness 0.2.x, the Jimeng desktop app installed and signed in,
credits available, and Node.js ≥ 22.5.

```bash
git clone https://github.com/MokoKing666/dsh-jimeng.git
cd dsh-jimeng
dsh plugin --profile desktop add .
```

If the tools do not appear afterwards, restart dsh once.

## Why models are not hard-coded

The plugin calls the same two endpoints the web client uses:

```
POST /mweb/v1/get_common_config                → image models
POST /mweb/v1/video_generate/get_common_config → video models
```

The response carries `model_req_key`, `model_name`, `duration_option`,
`video_aspect_ratio_option` and `feats`. The plugin treats that as data, so a new
model shows up without a plugin release.

## How it works

The desktop app is Electron and stores its session cookies in plaintext SQLite:

```
%APPDATA%\dreamina-desktop\Partitions\dreamina-web\Network\Cookies
```

The plugin reads `sessionid` with `node:sqlite`, signs requests the way the web
client does (`md5("9e2c|" + last 7 chars of uri + "|7|5.8.0|" + timestamp + "||11ac")`),
then calls `/mweb/v1/aigc_draft/generate` to submit and `/mweb/v1/get_history_by_ids` to poll.

## Known limitations

- **Cookies cannot be read while the Jimeng client is running** (exclusive file lock).
  Quit the client, or set `cookieHeader` manually.
- Text-to-image and text-to-video only; image-to-video is not wired up yet
- One task at a time
- Depends on the desktop cookie storage format
- The API is unofficial and may change
